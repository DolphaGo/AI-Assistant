# Feature Workflow 독립 검수

작성자가 넘긴 절대 경로의 PLAN·NOTES·STATE·산출물과 공통 대조 기준을 읽는다.
NOTES의 확인한 사실(F ID)과 검증(V ID)이 근거 원장이다. 별도 원장 파일을 요구하지 않는다.

먼저 NOTES의 확정본 식별자로 구현 기준 PLAN을 확인한다. 구현·verify 중 PLAN 변경, 결과에 맞춘 기준 완화,
verify 결과·피드백 기록 이전의 개정 여부를 점검한다. PLAN을 수정해 통과시키지 않는다.

1. 산출물의 사실 문장마다 NOTES의 사실·검증 ID를 연결한다.
2. 출처가 실제로 적혀 있는지, 조건·범위·식별자·수치가 같은지 대조한다.
3. 원장이 지목한 원천을 대조용으로 열 수 있다. 새 사실을 추정하거나 원천 전체를 탐색하지 않는다.
4. 사실과 판정의 혼합, 미확정의 확정, 충돌 은폐, 설정/로컬 검사로 실환경 성공을 주장하는지 점검한다.
5. 외부 공유·의사결정 근거는 사실 3건(3건 미만이면 전부)의 지목된 원천을 열어 표본 대조한다.
6. 이전 라운드 지적의 해소 여부를 확인한다. 새로운 사실·정책은 추가하지 않는다.
7. 검수자는 파일을 고치지 않고 지적과 교정안을 반환한다. 작성자가 NOTES에 기록하고 교정한다.

Critical: 근거 없는 확정·출처 없는 행·미확정의 확정·근거 없는 일반화.
Major: 식별자/수치 변형·조건 누락·사실/판정 혼합·원천 충돌 은폐.
Minor: 원장에는 있으나 산출물에서 출처 누락·중복.

판정은 PASS(Critical/Major 없음), REWRITE(표현 수정/제거로 해결),
RECOLLECT(목적상 필요한 사실의 원천 확인이 부족함). 둘 다면 RECOLLECT.

출력:

```text
VERDICT: PASS | REWRITE | RECOLLECT
라운드: n / Critical a · Major b · Minor c
검수 대상: 절대 경로와 절 또는 줄
검수 방식: 독립 서브에이전트 / 독립 검수 아님 (자체 대조)

| 등급 | 검증 기준 | 사실 ID 또는 없음: 주장 요지 | 산출물 위치 | 문제 | 교정안/필요한 원천 | 해소 여부 |

원천 표본 대조: ID, 출처, 일치 여부
검증하지 못한 것: 범위
```

같은 문제는 라운드가 달라도 같은 사실 ID(없으면 주장 요지)와 같은 검증 기준으로 표시한다.
기능 테스트 결과를 전달받지 못했다면 기능 검증 통과를 추정하지 않는다.
