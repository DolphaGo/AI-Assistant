# /feature-workflow:verify

여러 source 가 새 위치로 이관된 워크플로우에서 누락이나 의도치 않은 변경이 있는지 병렬 에이전트로 점검한다.

## 사용법

```
/feature-workflow:verify
/fw-verify
```

## 동작

1. PLAN.md 의 §모듈 이관 맵 또는 PROGRESS.md 의 매핑 표를 읽음
2. 검증할 source 가 N 개면 N 개 에이전트를 사용 가능한 병렬 agent/subagent 도구로 병렬 spawn
3. 각 에이전트는:
   - 원본 디렉토리의 모든 대상 파일 목록 만들기
   - 매핑 규칙대로 새 위치 계산
   - 새 위치에 파일 존재 여부 확인
   - diff 로 내용 비교 — package/import 차이만 있어야 함, 그 외 변경은 의심 케이스로 보고
   - 누락/의심 보고
4. 모든 에이전트 결과 받은 후 종합 보고:
   - 정상 이관 N/N
   - 누락 (있다면)
   - 의심 케이스 (있다면)
5. 누락 발견 시 사용자에게 즉시 보강할지 묻기

## 에이전트 프롬프트 템플릿

```
{source_root} 의 모든 파일이 {dst_root} 로 빠짐없이 이관됐는지 검증해줘.

## 매핑 규칙
{매핑 표}

## 검증 방법
1. 원본의 모든 .java 파일 목록 생성
2. 각 파일의 새 위치 계산 (매핑 규칙 적용)
3. 새 위치에 존재 확인
4. diff: package/import 차이만 허용. 그 외 본문 변경은 의심.

## 보고 형식
- 정상 이관: M개
- 누락: file_path 목록
- 의심: file_path: 변경 내용

300 단어 이하 간결하게.
```

## 발견된 누락 처리

발견되면 사용자에게:
1. 즉시 별도 phase 로 보강 (`/feature-workflow:resume` 후 누락 보강)
2. 또는 wrap up 단계에서 일괄 처리
사용자 선택에 따라 진행.

## 언제 호출하나

- 여러 source 를 새 위치로 이관한 phase 완료 후
- 워크플로우 마지막 단계 직전
- 사용자가 "잘 옮겨졌는지 확인해줘" 요청 시
