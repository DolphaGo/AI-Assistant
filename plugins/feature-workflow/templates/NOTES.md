# 작업 노트

## 확인 대상

대상 경로·브랜치·커밋·확인 시각. 저장소가 아니면 해당 없음으로 표시한다.
이 문서는 작업 재개용 기록이며 현재 동작은 관련 원천에서 재확인한다.

## 확인한 사실

| ID | 사실 (대상·분기·guard·결과, 식별자·수치 원문) | 출처 | 확인 방법·시각 |
|---|---|---|---|

사실만 적는다. 해석·판정은 아래 결정 배경에 해당 F ID와 함께 기록한다.
2차 기록이면 확보하지 못한 1차 원천을 표시한다.

## 검증

| ID | 대상·범위 | 실제 실행 명령·확인 방법 | 실제 출력 요지·종료 코드 | 확인 시각 |
|---|---|---|---|---|

실행하지 않은 계획·예시는 결과로 쓰지 않는다. 비밀값이 섞인 출력은 마스킹한다.

## PLAN 확정본·피드백·개정 이력

확정 시점·승인/위임 근거와 확정본의 Git 커밋 또는 파일 해시를 기록한다.
구현·verify 중 새 결정·요구·충돌은 이곳에 기록하고 PLAN은 고정한다.

| 확정본 | verify 결과(V ID·미완료/미검증 사유 포함) | 피드백 주체·내용 | 변경 제안·수용/보류·이유 | 개정 전후·권한 근거·재확정본 |
|---|---|---|---|---|

verify 결과와 피드백을 먼저 기록한 뒤에만 PLAN을 개정한다. 사용자 피드백과 자체 검토를 구분한다.
개정이 없으면 없다고 기록한다. 결과를 맞추려고 기존 검증 기준을 바꾸지 않는다.

## 이관 맵 / 리스크 / 트러블슈팅 / 결정 배경

해당하는 항목만 작성한다. 사실 F ID와 해석·판정을 구분한다.
phase 상태와 next_steps는 STATE.json에만 기록한다.

## 검수

검수 대상·라운드·방식·판정(PASS/REWRITE/RECOLLECT)·미검증 범위를 기록한다.
자체 대조면 `독립 검수 아님 (자체 대조)`로 표시한다.

| 라운드 | 등급 | 검증 기준 | 사실 ID 또는 주장 요지 | 산출물 위치 | 지적·교정 | 해소 여부 |
|---|---|---|---|---|---|---|
